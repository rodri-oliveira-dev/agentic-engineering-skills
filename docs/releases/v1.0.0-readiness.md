## Intended scope

Version 1.0.0 is intended to contain the ten canonical skills under `.agents/skills/`, the structural validator, fixture-based behavioral evaluation recorder, the managed Claude Code installer, the generated marketplace plugin infrastructure, automated regression tests, and platform and contributor documentation. It does not include hosted services, agent runtimes, new skills, published marketplace releases, or guarantees about third-party model behavior.

## Completed functionality

- Ten skills exist in the canonical catalog with bounded responsibilities and on-demand references.
- Structural validation covers metadata, canonical layout, local-reference containment, catalog safety, and known validator regressions.
- Scenario fixtures cover expected use, non-activation, insufficient information, operational failure or limitation, and destructive-operation handling where applicable.
- The behavioral evaluator validates fixture coverage and can record real runs separately from structural results; no real evaluation record is present.
- The Claude Code installer supports dry-run, managed install/update, manifest-based overwrite protection, and managed uninstall.
- Project-level Codex and Copilot use the canonical directory without a duplicated source tree.
- A deterministic `agentic-engineering` plugin packages all ten skills for OpenAI Codex, GitHub Copilot CLI, and Claude Code marketplaces without adding MCP servers, hooks, agents, credentials, or host-specific skill edits.
- Package generation rejects traversal, source and package symlinks, symlinked output parents, untracked package files, and modified generated files; SHA-256 inventory and canonical reconstruction provide complementary drift checks.

## Limitations and pending tests

- No live-agent behavioral records have been committed. Representative scenarios remain pending execution.
- The final marketplace commit still needs successful CI on the configured Ubuntu/Python 3.11 and Windows/Python 3.13 jobs; the recorded successful run predates these changes.
- External documentation links are reviewed but not fetched by offline tests.
- PyYAML 6.0.4 is pinned, but its PyPI release does not publish provenance attestations. No complete software-composition or reachability analysis has been recorded.
- The embedded SHA-256 inventory detects drift but does not authenticate a publisher that can rewrite both package files and hashes; Git history, protected publication, and release checksums remain necessary.
- Copilot CLI and Claude Code were unavailable locally, and the remote marketplace commands cannot succeed from the default branch until this PR is merged.
- Manual copies for Codex and Copilot have no ownership manifest; users must review local changes before replacing them.
- Concurrent filesystem mutation during installer execution is outside the atomicity guarantees of individual file replacements.

## Publication conditions

A maintainer may authorize publication only after all of the following are evidenced on the exact release commit:

1. all required local checks and both CI matrix jobs pass;
2. no unresolved high-impact security defect remains in the release scope, and the dependency vulnerability and provenance assessment is complete, with its findings and limitations recorded;
3. at least a controlled priority-platform evaluation covers expected activation, non-activation, insufficient information, operational limitation, and destructive-operation refusal or confirmation without invented results;
4. installation and update instructions are rechecked against the shipped scripts and selected platform clients;
5. release notes identify supported evidence, limitations, dependency versions, and any skipped checks;
6. the tag, source archive, and any checksums are prepared from the reviewed commit without changing canonical content;
7. a maintainer explicitly approves publication.

Until these conditions are met, the readiness decision remains **not authorized**.
