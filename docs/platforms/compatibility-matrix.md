# Platform compatibility matrix

This matrix separates vendor support, repository structural evidence, and runtime behavior. A shared file format or documented discovery path does not by itself prove that a skill activates correctly or produces a useful result.

The historical prerelease conclusion is preserved in [Version 1.0.0 readiness](../releases/v1.0.0-readiness.md); the actual publication and its remaining limitations are recorded in the [Version 1.0.0 publication record](../releases/1.0.0-publication.md).

## Status definitions

- **Supported:** current official platform documentation recognizes the format, location, or workflow, and this repository uses it as documented.
- **Structurally validated:** deterministic repository checks verified metadata, layout, references, or generated-file integrity without exercising model behavior.
- **Installation validated:** a named client completed an installation in a specified environment; this does not imply live discovery, activation, or behavioral quality.
- **Behaviorally validated:** controlled live-agent execution was observed and evaluated against recorded criteria.
- **Not tested:** no controlled runtime test of skill activation and instruction-following has been completed on that platform surface.
- **Unsupported:** the platform does not document the named location or workflow as a discovery mechanism; an adapter or another supported path is required.

## Evidence recorded for this change

- `python scripts/validate_skills.py --require-skills` validates the non-empty canonical catalog.
- `python -m unittest discover -s tests -v` validates portable metadata, canonical discovery structure, generated distribution integrity, idempotence, and safety boundaries.
- `python scripts/package_plugins.py check` reconstructs the marketplace package and manifests from `.agents/skills/` and fails on missing, stale, extra, or manually edited derived files.
- `python scripts/package_plugins.py verify` independently checks every generated package file against its embedded SHA-256 inventory.
- `npx --yes skills@latest add . --list` discovered exactly the ten canonical skills from the local checkout without installing them.
- `npx --yes skills@1.9.0 add rodri-oliveira-dev/agentic-engineering-skills --list` discovered the same ten skills from the public repository without installing them.
- Codex CLI `0.171.0-alpha.13` registered the public repository, listed plugin version `1.0.0`, and installed it into an isolated temporary `CODEX_HOME`; it did not launch a live agent workflow.
- GitHub Actions run [`45163692742`](https://github.com/rodri-oliveira-dev/agentic-engineering-skills/actions/runs/45163692742) passed the exact `1.0.0` release commit on Linux/Python 3.11 and Windows/Python 3.13.
- A read-only `codex exec --ephemeral --sandbox read-only` run enumerated the ten directories under `.agents/skills/`; it did not test activation or workflow behavior.
- GitHub CLI 2.94.0 successfully previewed `code-review` from the remote hidden catalog with `--allow-hidden-dirs`; it did not install or invoke the skill in Copilot.
- Copilot CLI and Claude Code were not present in the validation environment.
